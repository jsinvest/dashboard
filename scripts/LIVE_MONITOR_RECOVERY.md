# 프로그램·투자자·선물 CVD 공유 주소 복구

세 메뉴는 `live-monitors/connection.json`의 같은 외부 주소를 사용한다. 임시 주소가 사라지면 세 링크가 함께 실패한다. 수집기 정상 여부와 보기 서버·외부 연결·대시보드 주소 반영을 따로 검사한다.

1. 기존 프로그램·투자자·CVD 수집 세션과 실제 수신시각을 확인한다. 동작 중인 수집기·알림·월물·누적 원본·소유 세션은 재시작하거나 변경하지 않는다.
2. 보기 서버의 `http://127.0.0.1:8780/health`가 `app=readonly-trading-viewer`인지 확인한다. 다른 서비스가 이 포트를 점유하면 이를 외부에 노출하지 말고 원인을 조사한다.
3. 보기 서버나 외부 연결이 중단됐을 때만 기존 `restapi/live_dashboard_bridge/launcher.py`를 해당 설치 Python으로 실행한다. 이 실행기는 보기 서버와 터널만 시작하며 수집기를 조작하지 않는다. 실패하면 실제 로그를 읽는다. 주소 발급의 일시 오류는 간격을 두고 최대 두 번만 재확인한다. 주소가 발급됐다는 로그만으로 성공으로 판정하지 않는다.
4. 최신 main 기반 격리 작업공간에서 아래 검사를 실행한다. 읽기 전용 bridge의 `data/public.json`에 저장된 주소만 사용하며 비밀번호·토큰·PID·로그 경로를 공개 manifest로 복사하지 않는다.

```text
python scripts/sync_live_monitor_connection.py --root <checkout> --report <private-validation.json>
python scripts/sync_live_monitor_connection.py --root <checkout> --apply --report <private-validation.json>
```

`/health`의 실제 앱, 프로그램·투자자·CVD 로그인 화면 3개, 인증 없이 데이터 API에 접근했을 때 401을 반환하는지 모두 검사한 뒤에만 주소를 반영한다. 실패 시 기존 manifest를 보존한다. 같은 주소면 시각과 파일 bytes도 바꾸지 않는다. 이 검사는 수신 자료의 최신성이나 로그인 후 차트를 검증하는 대신이 아니다.

5. 주소가 달라진 경우 이번 유지보수에서는 `live-monitors/connection.json` 한 파일만 지정 스테이징한다. 현재 원격 main과 충돌을 확인하고 정상 push한다. 다른 사용자 변경이나 과거 자료를 섞지 않는다.
6. 같은 SHA Pages 성공, 캐시 우회 공개 manifest, 실제 프로그램·투자자·CVD 메뉴의 iframe/별도창 주소와 PC·모바일 표시를 확인한다. 기존 비밀번호로 실제 인증하며 인증을 우회하거나 검증용 비밀번호·세션을 공개 파일에 넣지 않는다. 로그인 성공과 당일 실제 데이터 수신을 구분한다.

아침 기존 프로그램 시작 예약과 22시 전체 점검에서 이 경로를 확인한다. 기존 예약시각·원래 수집/알림 범위는 유지한다. 공유 주소 유지보수는 일반 대화를 전송하거나 새 신호를 만드는 작업이 아니다.

대시보드 JS는 연결 manifest를 짧게 캐시하고 탭 재방문·수동 재확인 때 새 주소를 확인한다. manifest 조회가 실패하면 기존 iframe과 링크를 숨기고 재시도 버튼을 제공한다. 교차 출처 iframe의 네트워크 상태를 확인했다고 표시하지 않는다.

임시 터널은 PC·보기 서버·터널 프로세스가 동작해야 하며 재생성하면 주소가 달라질 수 있다. 고정 도메인이나 항상 켜진 서비스의 도입은 별도 설정이다.
