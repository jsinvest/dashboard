# 갱신 실패 복구와 완료 판정

`dashboard_upload_audit.py`는 검사만 한다. 필요한 자료의 날짜·스키마·공개 반영 오류가 남으면 `resolution.status=ACTION_REQUIRED`, 종료코드 2다. 종료코드 0은 필수 공개 파일 검사를 통과했다는 뜻이며 복구·원천 검증·공개 화면 확인이 완료됐다는 뜻이 아니다. 별도 화면 검증 전 `all_required_updates_complete`는 성공으로 확정하지 않는다.

선택 연구층·신고가 보조층 제외와 마감 전 최종분석 대기는 별도로 표시한다. 이들만 실패했다면 검증된 시장·현금·선물옵션의 독립 게시를 막지 않는다.

실패 시 작업 순서는 다음과 같다.

1. 현재 실행 호스트·프로세스·로그·실제 종료코드·공식 거래일을 새로 확인한다. 사용하지 않는 실행 환경의 과거 실패를 현재 차단 근거로 복사하지 않는다.
2. 공식 원천이 실제 게시됐는지 직접 확인한다. 전체 배치가 멈췄다는 이유로 모든 독립 단계의 복구를 포기하지 않는다.
3. 승인된 범위의 원인 수정과 필요한 최소 단계만 실행한다. 진행 중인 작업·이미 검증된 동일 결과는 중복 실행하지 않는다. 보안·인증·검증을 우회하지 않는다.
4. 원천 날짜·누적 누락·검증·정책 해시·실제 종료코드를 확인하고 대상 파일만 게시한다. 과거 날짜에 현재가를 넣지 않는다.
5. 해당 SHA 배포와 공개 PC·모바일 화면을 확인하고 실제 복구·게시 완료 여부를 기록한다. 검사 실행이나 설정 수정만으로 완료 보고하지 않는다.

필요 거래일이 하루 더 지났는데 같은 실패가 계속되면 새로운 갱신 실패다. 같은 원인이라는 이유로 미해결 핵심 항목을 무변화·정상으로 숨기지 않는다. 하루 한 번 마지막 공개일·필요 기준일·그날의 실제 시도·구체적인 남은 조치를 알린다. 추가 승인이 정말 필요하면 정확한 작업 한 가지로 요청한다. 이미 승인받은 수리 권한을 반복해서 요구하지 않는다.

2026-11-19에 시작 담당 예약은 사용자 승인으로 PowerShell 7 실행 호스트를 쓰도록 수정됐다. 해당 설정과 실제 실행 증거를 함께 확인하며 Windows PowerShell 5.1의 과거 차단 기록만으로 후속 현금 계산·전체 점검을 중단하지 않는다. 실행 정책 변경이나 Bypass는 사용하지 않는다.
